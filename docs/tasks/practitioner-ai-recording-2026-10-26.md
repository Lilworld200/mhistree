# Reviewed practitioner recording through Ask Mhistree — 2026-10-26

Scope: T21/T22/T24 maintenance of `/clinician/patients/[id]`, explicitly requested by the owner. Ask Mhistree previously only answered questions; its description and service had no reviewed record or note save path. The existing clinical-care service already provides attributed finalization with atomic timeline/current-state updates.

## Behavior and ownership

- `features/practitioner/patient-assistant.tsx` owns the extracted conversation UI. It shows current supported write categories, clarification, editable per-item review, event time, status, actual medication-use metadata, original practitioner spans, and explicit **Yes, save to …** / **No, save as private note** choices. A chat reply alone does not publish. Outstanding choices remain available after conversational yes/no. Successful saves refresh the patient profile; errors retain unsaved fields, and access denial clears the conversation/proposals and refreshes current access.
- `features/ai-chat/practitioner.ts` prepares suggestions, never clinical events. It checks current direct or explicit organization authority before and after generation, supplies current category permissions, and rechecks evidence. `conversation` enables the new preparation protocol; existing summary/question/assessment/draft callers remain supported. `previousRunId` loads only same-author/same-patient/same-connection runs at the current consent revision. Context is bounded to eight runs and18,000 characters, with a visible limitation on omission. Previous server submission timestamps/timezones anchor source turns; AI statements are not practitioner evidence. Private notes remain opt-in, and the direct UI continues using `includeOwnNotes:false`.
- `features/clinical-care/ai-proposal.ts` owns the shared proposal contract. Results/orders/document workflows are excluded from this conversational writer. Medication use, prescription, allergy, ongoing condition/issue, baseline, clinical finding, symptom and activity remain distinct. Unknown occurrence time stays unknown; suspected conditions remain suspected. Medication name/dose/frequency must be supplied rather than invented; missing or explicitly ambiguous details block patient-record publication. Private notes may retain incomplete information. Source spans and medication detail strings are checked against actual practitioner turns. Generated relationship IDs and unsupported body-site references are rejected.
- `features/clinical-care/ai-entry.ts` implements `savePractitionerProposal`. The browser supplies a stored run/item ID, destination, reviewed literal true and edited text. Patient, category, author, context, source timing and medication state come from the immutable stored proposal. Current RLS, consent revision and category-specific write authority are checked again. A read-only practitioner cannot save a note or record by forging the request. One stable item UUID keys save and finalization: retry/concurrent replay cannot duplicate; changing payload/destination conflicts.
- `saveWorkInAccess` composes existing private-work creation and `finalizeEntryInAccess` in one transaction. Source, draft, event, state, audit and outbox roll back together on failure. AI provenance is retained for clinical drafts and private notes. A note never enters patient timeline/Health; finalization records the responsible practitioner. Prescriptions use the existing separate Health projection and do not assert actual use. Medication-use/allergy/ongoing/baseline entries update existing persistent state.
- Direct and organization workspace POSTs support `ai-save`, and `ai` accepts optional `conversation`, `previousRunId`, and source `timezone`. Existing Origin/session/body guards remain. Initial-care contexts cannot use this AI path. Organization saves retain institution/context/assignment policy and cannot borrow direct permissions. This extends the organization transport; no separate organization chat redesign is claimed.
- `patient-detail-view.tsx` supplies actual write scope and access/refresh callbacks and updates the Ask Mhistree description. Shared review CSS retains the existing neutral/pill design. `workspace-view.tsx` labels provenance for notes as well as drafts. The medication explanation now says recorded use with an explicit source, rather than incorrectly calling every professional entry patient-reported.
