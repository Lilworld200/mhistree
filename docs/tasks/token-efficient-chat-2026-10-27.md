## Owners, API and storage

- context-plan.ts: deterministic timeline/summary routing; no extra model router or embedding call. Health topics, continuation/history cues and supported dates invoke timeline search. Greetings/unrelated ordinary chat use active history. This is explicit lexical routing, not universal semantic intent recognition.
- server.ts: latest contiguous active window, at most12 messages/10000 characters, preserving the full latest patient message. Compact ordinary policy is about4000 characters rather than11500; reply completion bound1024 rather than1536. Source dates are a separate private system-context map, never role-message prefixes. Timeline evidence provider projection excludes IDs, quotes and redundant version lineage; server retains full lineage for current-authority/source rechecks.
- timeline-search.ts/retrieval.ts: optional selective mode preserves other callers' default contracts. Current-head/RLS filtering precedes ranking; stress/stressed/anxiety aliases added. Ordinary chat selects at most6 relevant records and6000 characters, without unrelated recent/persistent lanes except an explicit broad overview. Supported single-day queries include ISO, English month/day, yesterday/today and prior weekday, resolved using the patient's timezone. Range event overlap uses local day boundaries; unknown occurrence dates may match source capture day but retain unknown event precision. Unsupported date phrases fall back to topic search and a clarification when needed; no claim of exhaustive history.
- extraction/context.ts: background extraction continues from submitted reviewed patient text. Projection bounded to6000 rather than16000 characters, latest4 patient messages, up to6 prior reports and4 relevant wider timeline candidates. The full server-side validation/eligible correction context remains intact. Wider candidates never authorize a speculative merge or clinical link.
- navigation provider/chat-view/POST /api/chat: `depart` carries owned target and departing conversation IDs for saved-chat switches; New chat retains its create action. Typed drafts remain usable during preparation; failure retains Retry and explicit Continue without earlier memory. Title generation remains separately cached and cannot block replies.
- memory.ts: a source watermark and120-second lease serialize work per departed conversation. One provider call merges retained prior summary with at most40 newest changed messages/16000 raw characters. Sources omitted by that explicit budget remain in raw chat; summary is marked bounded. No recursive preparation, raw historical search or global recent-memory lane. Strict source quotes/roles, current authority and superseded-source rechecks remain. Empty useful-content output still saves a checkpoint so it cannot loop on refresh.
- chat_session_summaries: one owning-patient-only row per conversation, replaced on changed departure, containing items, through_sequence, model/source fingerprint, source_from/source_through and separate updated_at. Original item capture clocks/timezones remain. The navigation target_sequence checkpoint limits automatic injection to the first patient reply of that new/resumed session; later relevant life-context questions may retrieve up to2 matching summaries, bounded to3000 stored-item characters. Ordinary health recall uses timeline. Snapshots are not stacked; old chat_memory_chunks remain archived, unused and unbackfilled.
- reply-text.ts: deterministic balanced-JSON removal of Source capture echoes (including multiline, repeated and fenced forms), with rejection of residual reserved metadata. Applied before new assistant storage, history delivery, UI rendering, assistant-history reuse and read-aloud. Patient source text is never sanitized or rewritten. A metadata-only/unsafe new output fails safely with the saved patient message retained; no automatic paid retry. Prompt restrictions reinforce the code boundary. This covers known metadata formats; it is not universal model-quality certification.

No new clinical writer, practitioner access, notification, auth bypass, account quota, provider switch or embedding index. Current corrected timeline heads override fallible summary recall; advice is never patient action. Selection/read rechecks do not themselves call an AI provider. Summaries can omit details and cannot prove ongoing/resolved symptoms.
