# Care Notes: private notes and structured patient records

Date: 2026-10-28. Status: implemented and verified locally; no hosted deployment or migration performed.

## Owner decision

Care Notes has exactly two creation destinations: **Private Note** and **Patient Record**. Use an exclusive segmented selector, with the selected option active and the other grey. Remove the redundant Type picker. Private notes have a useful topic, optional title and free-text note, with **Save Private Note** and a dedicated **Previous private notes** view. Patient Record has meaningful category labels and category-specific fields, an editable form and preview, explicit practitioner review, and **Save Patient Record**. Patient records continue to be viewed through Health/shared history rather than a second record browser in Care Notes.

This task addresses Care Notes. Talk to Mhistree and Care inbox retain their existing workflows and separate review boundaries. No inference/provider request is required to save a manually entered note or record.

## Implementation

- `clinical-care/care-notes-view.tsx`: segmented destination control; independent retained mode/category drafts; scoped categories; private title/content; structured record inputs; preview only when required details are complete; review acknowledgement; stable retry keys and immediate in-flight protection. Previous private notes are paginated and author-only, with existing versioned editing, explicit paused-work review/resume and retained archiving. Errors retain unsaved input and access denials clear fetched notes.
- `clinical-care/care-note-schema.ts`: shared server/client validation and faithful formatting. Medication use and prescription/recommendation are separate categories. Verified medicine name, dose and frequency are required for a patient record; ambiguous consequential details block publication. Actual use must be explicitly selected, actual dates stay distinct from prescribed course dates, and prescribing never establishes taking. Conditions/ongoing issues and allergies have suspected/confirmed certainty; optional reaction/severity information does not introduce a patient-verification gate. Baseline has name/value/unit; symptoms, activities and clinical observations have their own relevant fields. Blank event dates remain unknown; entered dates receive day bounds through the existing timezone-aware time resolver.
- `clinical-care/care-notes.ts`: new `saveCareNote` composes `saveWorkInAccess` and `finalizeEntryInAccess` in one current-authorised transaction. The patient must match the selected context. Current connection/initial-care metadata is share-locked before entering the restricted runtime role, without broadening grants. Note saves never create contributions or persistent health state. Reviewed records atomically save attributed work/source/event/state/audit, and retries bind to the same semantic payload. `privateNotes` reads only the author/context/patient's private work, twenty notes per page, with current policy checks and bounded cursors.
- Workspace transports: `save-note` POST and `view=private-notes` GET are supported on direct and organization/initial-care workspace endpoints under the existing cookie/Origin/access guards. No model is instantiated for these operations. Legacy `save`, `edit` and `finalize` APIs remain available.
- `workspace-view.tsx`: replaces the mixed Type/Category/free-text/AI capture creation area with CareNotesView. Unfinished pre-existing drafts and reminders retain their existing edit/resume/finalize controls in a separate disclosure. Finalized records are not mixed into the private-note browser.
- `health-records/schema.ts`: additive optional `body.careDetails` retains explicitly entered medication, condition/allergy and baseline fields. Existing records require no rewrite or database migration. Shared finalization now splits long reviewed text into supported source spans instead of failing at the single-span 500-character limit.
- `medication-recommendations.ts`: one shared `syncReviewedMedication` helper serves manual forms and existing reviewed AI proposals. Reviewed prescriptions create source-linked recommendations; explicit taking/stopped records update the linked use workflow. Recommendation disposition, actual use, patient commitments and historical events remain separate. Initial care retains its existing basis and does not fabricate a connected recommendation recipient.
