# Authentication core

T08 owns setup/recovery credentials, restricted setup sessions, app sessions and provider reconciliation. `server.ts` exports issueCredential, redeemCredential, completeSetup, signIn, signOut. `sessions.ts` verifies every current local session; `lib/auth/keycloak.ts` owns provider I/O and signed-token validation. No staff API accepts a patient password. Passwords are submitted only with the restricted patient setup bearer and never stored in app tables/logs. Tokens are32 random bytes, SHA256 digests at rest.

`tests/integration/auth.test.ts` uses actual Keycloak26.8 and native PostgreSQL18.4. Run `pwsh -File scripts/start-auth.ps1` separately, then `pnpm test:integration`. The setup downloads the official release if absent, runs Java25, binds loopback8181, generates ignored local test secrets, and imports only synthetic realm configuration. No real account/provider environment is needed. These development settings must never be deployed.

Provider choice replaces the unconfigured Clerk candidate with a supported contactless Keycloak adapter. It adds an operational service; hosted deployment, TLS, provider backups, SMTP/verified-contact screens and administrative separation remain explicit later gates. Username/password uses the provider's confidential direct-access grant for this first-party server adapter; do not expose the client secret to browsers. See `docs/contracts/auth.md` for the flow and limitations.

Issue/replacement checks a current staff session and designated privilege/evidence. Recovery denies local old sessions before provider calls; a failed provider revocation is durably pending and returned truthfully. Completing setup retries revocation before setting the patient password. Per-person advisory locks serialize replacement/setup across provider I/O without holding SQL transactions. The same reserved provider username recovers uncertain creation responses. Redemption consumes once atomically, and setup can never authorize clinical reads.

T10 transports must add same-origin/CSRF checks, secure HttpOnly SameSite cookies, trusted request-derived rate keys, sanitized validation envelopes and no credentials in URLs. T29 supplies staff screens; T33 supplies retry/reconciliation tooling. Internal registration actors must be established from verifySession; never trust request roles or account IDs. Account retirement/epoch always overrides an older valid provider JWT. Application sessions expire no later than the verified provider access token; refresh is not implemented and requires new provider authentication.
