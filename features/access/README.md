# Shared access and private delivery

T26-T31 update: organization producers now exist in features/organizations. Organization_initial_care and duplicate_review_merge_journal migrations extend the shared policy, not browser authority. canonical_person allows the survivor's patient context to read retained original history; provider contexts still require their own original connection and consent origin scope. Patient connection controls resolve canonical ownership without unioning grants. Merge/reversal and organizational status/membership changes invalidate revisions and pause dependent work. Tests cover independent direct access surviving staff removal and merge isolation. Read docs/contracts/identity-access.md for current semantics; future-tense producer references below are historical foundation context.

Policy owner: PostgreSQL `mhistree.can_access` in the T09 migration. `withAccess(pool,session,selection,work)` verifies current app session, validates a strict selection (no actor/role fields), establishes transaction-local context, and switches to `mhistree_runtime`. `authorize` invokes the same policy used by RLS. Never use a context object as a perpetual grant or union direct/org permissions. No authority comes from browser role metadata.

The policy checks patient ownership or current qualification, connection, latest immutable consent/categories/exclusions/origin partitions, organization approval, membership privileges and assignment ceiling. Author-only draft/private access still needs that valid path. Initial care is a distinct evidence-backed basis for an unactivated person, limited to its original context; it opens no other history. Producers for grants/qualification/membership arrive later; fixtures populate them only inside tests.

`revokeConnection` verifies patient ownership, revokes and increments revision, pauses pending dependent work, and commits audit/outbox atomically. Repeated revocation is harmless. Fresh eligibility never resumes paused work. T17/T27 will supply consent/reconnection/assignment screens and explicit review transitions.

`preparePublication`/`recheckPublication` carry a narrowly scoped, server-only resource/context/session ticket and connection revision. Construct resource metadata from authorized stored rows, never submitted JSON. Revision changes invalidate tickets even after reconnection. Tickets expire with sessions; they are not a durable delegation mechanism. T11/T13/T16 workers must use this check at publication and add their own durable source/job lease contracts; never return the ticket to a browser or serialize its bearer into logs.

`private-files.ts` reads authorized private metadata under RLS, obtains bytes via an opaque-key adapter, verifies checksum/length, rechecks authority and audits the read before returning. No public URL is created. The test reads a real synthetic local file and revokes access during storage I/O. T13 owns upload/quarantine/parsing and the chosen production private-storage adapter. A transport must serve bytes privately without shared caching; previously delivered bytes cannot be recalled.

Database boundary: schema is private and inaccessible to public/anon; no browser DB credentials. Clinical runtime has no authority-table mutation rights or session-table read rights. Sources/contributions/heads/state/private-file metadata use RLS; policy is a restricted-search-path definer function. Migration/admin ownership is privileged and not a request role. The configured backend role must be allowed to SET ROLE mhistree_runtime; never grant this role to Supabase anon/authenticated. Hosted deployment grants remain to be rehearsed separately.

Tests: `tests/integration/access-records.test.ts` and authentication suite. Consumers: every T10+ clinical read/write/file/AI operation; T27 assignment producers; T31 origin-preserving merge; T32 full cross-consumer revocation. Current proof is core services and real PostgreSQL, not absent UI or future AI streaming.
